# 容器部署说明

本文档说明平台 Docker 镜像的构建、启动、目录挂载与环境变量配置。
容器内仓库根为 `/app`，配置文件为 `/app/config/config.docker.yaml`（已打入镜像）。

---

## 1. 构建镜像

```bash
# 仓库根目录执行（前端在镜像内构建为 web/dist）
docker build -t yourname/lianghua:latest .
```

## 2. 启动

### 方式一：docker compose（推荐）

```bash
docker compose up -d
```

`docker-compose.yml` 中只有 `/data` 一个挂载点，配置用镜像内置的
`config.docker.yaml`。

### 方式二：docker run

```bash
docker run -d --name lianghua \
  -p 8000:8000 \
  -v D:/lianghua-data:/data \
  -m 6g \
  yourname/lianghua:latest
```

启动后访问 `http://localhost:8000`。容器需能访问外网（baostock / akshare 数据抓取）。

---

## 3. 目录挂载

**唯一必须挂载的是 `/data`**，容器内所有持久化数据都在里面：

| 容器内路径 | 用途 | 说明 |
|---|---|---|
| `/data/market` | 日K Parquet（`{code}.parquet`） | 核心数据，务必持久化 |
| `/data/market/index_daily` | 指数日线 Parquet | 大盘汇总报告用 |
| `/data/meta.db` | SQLite 元数据 | 任务、脚本登记、断点表 |
| `/data/outputs` | 任务日志、报告产物 | `outputs/logs`、`outputs/reports` |
| `/data/raw/daily` | 原始层日K CSV | 获取数据时落盘，可重建 Parquet |
| `/data/raw/factor` | 原始层复权因子 CSV | 同上 |

要求：

- 宿主机目录需可读写（容器默认 root 运行）。
- 不要放在 SMB/网络盘上，SQLite 在网络文件系统上不可靠。
- Windows 宿主机建议用纯英文路径，避免中文路径映射问题。
- 子目录由程序按需自动创建，首次启动保证 `/data` 本身存在即可。

### 历史 CSV 转 Parquet 的额外挂载

「历史CSV转Parquet导入」脚本读 `daily_dir`、`factor_dir`，容器内分别指向
`/data/raw/daily`、`/data/raw/factor`。把宿主机历史 CSV 目录挂到这两个路径（只读即可）：

```bash
docker run -d --name lianghua \
  -p 8000:8000 \
  -v D:/lianghua-data:/data \
  -v G:/量化数据/data/daily:/data/raw/daily:ro \
  -v G:/量化数据/data/factor:/data/raw/factor:ro \
  -m 6g \
  yourname/lianghua:latest
```

## 4. 环境变量

### 镜像内置（Dockerfile 已设置，无需手动指定）

| 变量 | 值 | 用途 |
|---|---|---|
| `APP_CONFIG` | `/app/config/config.docker.yaml` | 指定配置文件路径 |
| `TZ` | `Asia/Shanghai` | 时区（影响定时任务与日志时间） |
| `PYTHONIOENCODING` | `utf-8` | 避免中文日志乱码 |
| `PYTHONUNBUFFERED` | `1` | 日志实时输出 |

### 运行时可设置

| 变量 | 默认 | 用途 |
|---|---|---|
| `SMTP_PASSWORD` | 空 | SMTP 授权码；**仅当要发报告邮件时必填**，与配置里的 `smtp.username` 配合 |
| `DATA_DIR`（compose） | `./data` | 宿主机 `/data` 对应目录 |
| `PORT`（compose） | `8000` | 宿主机映射端口 |
| `CONFIG_FILE`（compose） | `./config/config.docker.yaml` | 覆盖配置文件的宿主机路径，默认**不挂载** |

发邮件还需要在配置文件中提供 `report.recipients` 与 `smtp.username`；
不配置收件人时报告任务会记录「未配置 report.recipients，跳过发送」。

## 5. 覆盖配置文件（可选）

镜像内置配置已适配容器路径，一般不需要覆盖。确需修改时：

1. 复制 `config/config.docker.yaml` 到宿主机并修改；
2. 在 `docker-compose.yml` 的 `volumes` 中取消该行注释：

```yaml
- "${CONFIG_FILE:-./config/config.docker.yaml}:/app/config/config.docker.yaml:ro"
```

注意：宿主机文件**必须真实存在**。若路径不存在，Docker 会创建一个同名目录，
`APP_CONFIG` 读到目录后启动报错。

---

## 6. 首次启动步骤

1. 启动容器，确认 `http://localhost:8000/api/health` 返回 `{"status":"ok"}`。
2. 「股票」页 → 初始化股票列表（拉取 A 股基础信息）。
3. 「数据管理」页 → 获取数据（首次为空库，默认从 2005-01-01 起，耗时长）。
4. 如已有历史 CSV：先挂载 `/data/raw/daily`、`/data/raw/factor`，再在「策略」页
   运行「历史CSV转Parquet导入」一次性任务。
5. 「报告」页可手动触发每日大盘汇总；定时任务默认工作日 18:00 执行。

## 7. 常见问题

| 现象 | 原因与处理 |
|---|---|
| 启动即报配置读取失败 | `APP_CONFIG` 指向的是目录而非文件（见第 5 节） |
| 任务日志出现 `ImportError: cannot import name ... from 'app.config'` | 旧镜像；子进程缺少 `PYTHONPATH`，重新构建镜像即可 |
| 任务 exit_code=`3221225786` | Windows 控制台 Ctrl+C 中断（`STATUS_CONTROL_C_EXIT`），不是程序错误 |
| 任务 exit_code=`137` | 内存不足被 OOM kill；历史 CSV 转换峰值约 3GB，建议 `-m 6g` |
| 指数数据重启后消失 | 配置缺少 `index_dir` 或未指向 `/data` 下目录 |
| 获取数据一直 0 条 | 容器无法出网，或 baostock 会话失效（任务日志会记录登录失败原因） |
