# 获取数据原始层落地设计方案

> 版本：v0.1（待评审）
> 状态：待评审
> 定位：为「获取数据」增加「每日股票数据」与「因子数据」两层原始留存（按配置目录落 CSV），支撑审计与可重建；终态按股票分文件的 Parquet 不变。

---

## 1. 背景与目标

**现状**：`POST /api/datasets/{id}/run` → `task_service._run_ingest` → `ingest.run_fetch` 逐交易日横扫全市场：取当日不复权日K（`bars`）+ 当日复权因子事件（`factors`）→ 按 code join、因子前向填充、算前/后复权价 → `df.groupby("code")` 逐只写/合并 `{code}.parquet`。**两层原始数据在内存中 join 完即丢弃**，磁盘上只剩「按股票分组」的终态 parquet。

**遗留脚本**（`script/`，只作参考）本就有三层：`每日/{date}.csv`（日K日分组）、`复权因子每日/{date}.csv`（因子事件）、`合并/`（按股票）。平台版少了前两层。

**目标（目的 A：审计 / 可重建）**：每个交易日把「当日全市场不复权日K」与「当日复权因子事件」按**遗留脚本同目录、同格式**分别落 CSV，使历史段（2005 起，已存在于遗留目录）与平台新写的段无缝拼接；`app/services/csv_import.convert` 可直接读取整段重建，无需改重建链路。

**非目标**：不做独立数据集卡片/覆盖度展示（不做 B）；不改动 `script/`、`strategy/` 脚本；不改动终态 Parquet 结构（仍按股票分文件）；不改前端。

## 2. 配置

`config/config.yaml` 顶层新增两个键（与 `data_dir` 同级）：

```yaml
data_dir: F:\market                                     # 终态 Parquet（不变）
daily_dir: "G:\\各种资料\\量化数据\\A股日K日分组"        # 每日股票数据（日K日分组）
factor_dir: "G:\\各种资料\\量化数据\\复权因子每日"        # 因子数据（复权因子每日）
```

- `app/config.py` 的 `Config` 新增 `self.daily_dir` / `self.factor_dir`，复用 `_p(ROOT, ...)`：绝对路径直接用、相对路径解析到仓库根。
- `config/config.docker.yaml` 同步新增容器内路径：`daily_dir: /data/raw/daily`、`factor_dir: /data/raw/factor`。
- 默认值即上述 G: 路径（用户已确认）。

## 3. 原始层落盘规格

沿用遗留脚本口径，**纯 CSV、UTF-8 BOM（`utf-8-sig`）、带表头、文件名 `{date}.csv`**：

| 层 | 路径 | 列（顺序固定） | 说明 |
|---|---|---|---|
| 每日股票数据 | `{daily_dir}/{date}.csv` | `date, code, open, high, low, close, preclose, volume, amount, adjustflag, turn, tradestatus, pctChg, peTTM, pbMRQ, psTTM, pcfNcfTTM, isST`（18 列） | 当日全市场**不复权**日K原样；`code` 保留 `sh.`/`sz.` 点前缀 |
| 因子数据 | `{factor_dir}/{date}.csv` | `code, dividOperateDate, foreAdjustFactor, backAdjustFactor, adjustFactor`（5 列） | 当日复权因子事件原样；`code` 保留点前缀 |

**写入规则**：

- **幂等**：目标文件已存在则跳过（与遗留脚本一致，天然支持续抓、不重写历史）。
- **空日标记**：当日无数据（日K为空 / 无除权事件）时，写「仅表头的空 CSV」作为已处理标记（遗留同款）。
- **原子落盘**：先写同目录临时文件再 `os.replace`，避免中断留下半个文件。
- **原始优先**：日K层从数据源返回的原始行取值（仅裁剪为上述 18 列，剔除摄取过程追加的 `qfq_factor`/`hfq_factor` 键）；因子层取原始字段，而非归一化后的字段。

## 4. 代码改动点

### 4.1 新增 `app/services/raw_store.py`

职责单一：原始层写盘与存在性判断，不参与任何计算。

```python
DAILY_RAW_COLS  = ["date","code","open","high","low","close","preclose","volume","amount",
                   "adjustflag","turn","tradestatus","pctChg","peTTM","pbMRQ","psTTM","pcfNcfTTM","isST"]
FACTOR_RAW_COLS = ["code","dividOperateDate","foreAdjustFactor","backAdjustFactor","adjustFactor"]

daily_path(root, date) -> Path          # {root}/{date}.csv
factor_path(root, date) -> Path
has_daily(root, date) -> bool           # 文件存在
has_factor(root, date) -> bool
write_daily(root, date, bars) -> Path | None    # 已存在则返回 None（跳过）
write_factor(root, date, factor_rows) -> Path | None
```

- `write_daily` 按 `DAILY_RAW_COLS` 裁剪（缺列补空、多余列丢弃）；`write_factor` 按 `FACTOR_RAW_COLS` 裁剪。
- 因子行字段回退（兼容既有 `_fetch_factors` 口径与测试假数据）：`code ← raw_code or code`、`dividOperateDate ← dividOperateDate or date`、`foreAdjustFactor ← foreAdjustFactor or qfq_factor`、`backAdjustFactor ← backAdjustFactor or hfq_factor`、`adjustFactor ← adjustFactor 或空`。
- 目录不存在时自动创建。

### 4.2 `app/services/ingest.py`

- `run_fetch` 新增可选参数 `daily_dir=None, factor_dir=None`。
  - 两者均提供时启用原始层；任一为空则原始层关闭（保持既有行为，便于单测与向后兼容）。
- 每个交易日抓完数据后、在 `df.empty` 判断前，调用原始层写盘。注意 `_fetch_factors(date)` 的返回列表既用于 join、也用于原始层落盘（4.3 已使其携带原始字段），**只查一次**：

```python
factor_rows = _fetch_factors(date)                 # 原始字段 + 归一化字段
factors = {f["code"]: f for f in factor_rows}      # 归一化 code 作 join 键（不变）
# …按 code join、前向填充、算复权价（逻辑不变）…
if daily_dir:  raw_store.write_daily(daily_dir, date, bars)
if factor_dir: raw_store.write_factor(factor_dir, date, factor_rows)
```

- **跳过条件调整（关键）**：原「`date <= min_done` 即整日跳过」会让原始层漏写。改为：

```python
skip_day = (min_done is not None and date <= min_done
            and (not daily_dir  or raw_store.has_daily(daily_dir, date))
            and (not factor_dir or raw_store.has_factor(factor_dir, date)))
```

  即：只有当**断点位点已覆盖该日**且**原始层两个文件都已存在**时才整日跳过；否则照常抓取并补写原始层。这样存量 parquet 已覆盖、原始层缺文件的日期会被补抓，原始层不留洞（原始层关闭时行为与现状完全一致）。

- 日志：每日写盘后追加一行，注明原始层两个文件是「新写」还是「已存在跳过」。

### 4.3 `app/datasources/baostock.py`

`adjust_factors` 目前丢弃了 `dividOperateDate`/`adjustFactor` 且 code 去点，原始层无法还原。改为**在原归一化字典上追加原始字段**（**不新增查询**）：

```python
{ "date": date, "code": "sh600000",        # 归一化（摄取落 parquet 用，契约不变）
  "raw_code": "sh.600000",                 # 原始 code（带点）
  "dividOperateDate": ..., "foreAdjustFactor": ..., "backAdjustFactor": ..., "adjustFactor": ...,
  "qfq_factor": ..., "hfq_factor": ... }   # 归一化（摄取用，契约不变）
```

`_fetch_factors` 的既有契约（返回含 `code`/`qfq_factor`/`hfq_factor` 的字典）保持不变，现有测试与落 parquet 逻辑零改动。`app/datasources/base.py` 的 `adjust_factors` docstring 同步说明。

### 4.4 `app/services/task_service.py`

`_run_ingest` 读取 `self.cfg.daily_dir` / `self.cfg.factor_dir`，传入 `ingest.run_fetch(..., daily_dir=..., factor_dir=...)`；启动日志中打印两个原始层目录。

### 4.5 不改动

`script/`、`strategy/`、终态 Parquet 结构、`web/` 前端、`stock_freshness` 断点表结构。

## 7. 风险与注意事项

- **原始层启用后的补抓**：若 `daily_dir`/`factor_dir` 指向的目录历史不全，`获取数据` 会在 `dates` 范围内补抓缺失日期（这正是目的 A 的预期），日志会明确标注；`start_date` 留空时窗口以 `dataset.latest_data_date` 为起点，不会回溯到 2005。
- **外部盘路径**：`daily_dir`/`factor_dir` 为绝对路径（G: 盘），目录不可写时原始层写盘失败应记录日志并**不阻断**终态 parquet 摄取（原始层是附加留存，非主链路）。
- **格式绑定**：原始层格式与遗留脚本强绑定，若后续要改格式（如 parquet），需同时改 `csv_import` 重建链路——本次不做。
- **git 规矩**：只提交本次新增/修改的代码、测试与文档；`config/config.yaml` 与 `script/导入历史数据-转parquet.py` 的既有未提交路径改动另行评估，不混入本次提交。
