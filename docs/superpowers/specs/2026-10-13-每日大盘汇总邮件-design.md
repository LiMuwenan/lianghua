# 每日 A股大盘汇总邮件 · 设计稿

> 日期：2026-10-13
> 状态：待评审
> 定位：在量化平台「获取数据」完成、收盘数据齐备后，每天自动生成一封 **HTML 邮件**，汇总 A股大盘全貌，发送到指定邮箱。个人自用，不对外、不做投顾建议。

---

## 1. 背景与目标

平台已具备：全市场个股日K（Parquet，24 列含复权/估值）、`stock` 名称与行业映射、APScheduler 调度与 `task_run` 任务体系。用户希望"每天获取完数据后，把 A股大盘数据汇总成一份报告推送到邮箱"。

**推送通道决策（2026-10-13）**：最初考虑微信（小程序/公众号/订阅号），经核实——**个人主体只能注册订阅号、不能注册/认证服务号，也无法使用模板消息/订阅通知接口**，个人主体原生通道做不到"每天自动精准推送给指定用户"。故改为**邮件（SMTP）**，无平台限制、无认证门槛、无额度限制。

**目标**：每天收盘数据齐备后，自动汇总 A股大盘 6 大板块（指数/宽度/量能/估值/行业/个股热度），渲染为 HTML 邮件并发送至指定邮箱。

---

## 2. 需求范围

### 2.1 第一版包含（①-⑥）

| 板块 | 内容 |
|---|---|
| ① 核心指数 | 8 只指数的点位、涨跌幅、成交额 |
| ② 市场宽度 | 涨跌/平盘家数、涨跌停家数（近似）、停牌家数 |
| ③ 量能 | 全市场成交额、成交量、换手率；对比前一日与 5 日均值（放量/缩量） |
| ④ 估值 | 全市场 PE/PB 中位数 + 近一年分位 |
| ⑤ 行业 | 按行业分组的涨跌幅，领涨/领跌 TOP5 |
| ⑥ 个股热度 | 涨幅榜/跌幅榜 TOP10、涨停家数 |

### 2.2 非目标（后续迭代）

- ⑦ 资金面（北向资金、两融余额、主力资金）——依赖外部数据源、接口不稳定；
- 邮件内嵌走势图（原"方案②③"的图表）；
- 精确连板统计；
- 多收件人/多模板/多语言。

## 4. 总体架构与数据流

```
APScheduler 定时任务（工作日 18:00，可在页面改）
  │
  ├─ [数据就绪检查]  个股最新日期==最近交易日 且 指数最新日期==最近交易日
  │      ├─ 未就绪 → 不发信，记 skipped + 日志说明（可选发一封告警邮件）
  │      └─ 就绪  ↓
  ├─ [汇总计算]   读 index_daily/*.parquet + daily_price/*.parquet（DuckDB 跨股聚合）
  │                 → 输出指标 dict
  ├─ [渲染 HTML]  Jinja2 模板 → HTML 字符串
  ├─ [SMTP 发信]   ssl → 发件邮箱 → 收件邮箱
  └─ [落库归档]   task_run(kind=report) 记录 status/指标JSON/HTML路径/日志
```

- 沿用现有**进程内 APScheduler + `cron_task` 表**，新增 `kind=report` 的定时项；触发后走现有统一任务执行路径（串行锁、日志、状态）。
- 汇总任务为**秒级轻任务**，不涉及子进程超时 kill。

## 5. 数据源与存储

### 5.1 数据来源

| 数据 | 来源 | 落点 |
|---|---|---|
| 指数日线（新增） | baostock `query_history_k_data_plus(code, fields, start, end, frequency="d")` | `{index_dir}/{code}.parquet` |
| 个股聚合 | DuckDB 直读现有 `daily_price/*.parquet` | 不新增存储 |
| 行业映射 | 现有 `stock.industry` | 复用 |
| 交易日历 | 现有 `trade_dates` | 复用 |

### 5.2 指数清单（8 只）

| 类别 | 指数 | 代码 | baostock |
|---|---|---|---|
| 综合 | 上证综指 | `sh.000001` | ✅ |
| 综合 | 深证成指 | `sz.399001` | ✅ |
| 综合 | 创业板指 | `sz.399006` | ✅ |
| 综合 | 科创50 | `sh.000688` | ✅ |
| 规模 | 上证50 | `sh.000016` | ✅ |
| 规模 | 沪深300 | `sh.000300` | ✅ |
| 规模 | 中证500 | `sh.000905` | ✅ |
| 规模 | 中证1000 | `sh.000852` | 待实测 |

> 标"待实测"的采用"**取不到就自动跳过、不报错**"策略；实施时用一次查询验证 baostock 是否收录。

### 5.3 存储布局（分文件夹）

```
data/market/
├─ daily_price/{code}.parquet      # 个股（现有，24 列，含复权/估值）
└─ index_daily/{code}.parquet      # 指数（新增，约 10 列，无复权/估值）
```

- 指数 schema（约 10 列）：`date, code, open, high, low, close, preclose, volume, amount, pctChg`（baostock 指数接口返回字段，无 `turn`/`peTTM` 等，不做复权换算）。
- 新增 config 顶层键 **`index_dir`**（与 `data_dir` 并列）。
- 指数**不进**个股数据集扫描、不进 `stock_freshness`、不进个股选股器，保持个股语义干净。

## 6. 指标口径明细

| # | 指标 | 计算口径 | 数据 |
|---|---|---|---|
| ① | 指数点位/涨跌幅/成交额 | 直接取 index_daily 当日行 | index_daily |
| ② | 上涨/下跌/平盘家数 | 按 `pctChg` 正/负/零分别计数（剔停牌） | 个股 parquet |
| ② | 涨停/跌停家数 | **近似**：按 `pctChg` 阈值判定（见表下） | 个股 parquet |
| ② | 停牌家数 | `tradestatus != 1` 或 `volume == 0` | 个股 parquet |
| ③ | 全市场成交额/量 | `SUM(amount)` / `SUM(volume)` | 个股 parquet |
| ③ | 平均换手率 | `AVG(turn)` | 个股 parquet |
| ③ | 放量/缩量 | 当日成交额 vs 前一交易日、vs 近 5 日均值 | 个股 parquet（按日聚合历史） |
| ④ | PE/PB 中位数 | `MEDIAN(peTTM)` / `MEDIAN(pbMRQ)` | 个股 parquet |
| ④ | 近一年分位 | 当日中位数在近一年该序列中的分位 | 个股 parquet |
| ⑤ | 行业涨跌幅 | 按 `industry` 分组求 `AVG(pctChg)`，取领涨/领跌 TOP5 | 个股 parquet + stock.industry |
| ⑥ | 涨/跌幅榜 TOP10 | 按 `pctChg` 排序（剔停牌、剔除上市首日） | 个股 parquet |
| ⑥ | 涨停家数 | 同 ② 涨停口径 | 个股 parquet |
| — | 一句话结论 | 由"指数涨跌 + 涨跌家数比 + 放量缩量"规则生成 | 汇总结果 |

**涨停判定阈值（近似）**：主板 ±10%、创业板/科创板 ±20%、ST/*ST ±5%、北交所 ±30%；以 `pctChg` 达到阈值（含容差）判定。邮件中注明"涨跌停为近似口径"。

**原则：数据缺失不造假** —— 任一板块数据缺失时，对应区块显示"数据缺失"，不臆造数值。

## 7. 邮件模板（HTML）

- 标题：`A股每日大盘汇总 | YYYY-MM-DD`
- 区块顺序：核心指数表 → 市场宽度 → 量能 → 估值 → 行业 → 个股热度 → 一句话结论。
- **A股红涨绿跌**；纯 `table` + 内联 CSS 布局（避开 flex/grid、外链 CSS/JS），适配 Outlook/QQ/手机邮箱。
- 同时归档一份 HTML 到 `outputs/reports/`，便于事后查看与排障。

## 9. 触发与调度（B 方案）

- 独立定时任务：示例 cron `0 18 * * 1-5`（工作日 18:00，可在页面改）。
- 触发流程：先做**数据就绪检查**（个股与指数最新日期均 == 最近交易日）：
  - **就绪** → 汇总 → 渲染 → 发送；
  - **未就绪** → 不发送，`task_run` 记为 `skipped` 并写明原因（可选发一封告警邮件）。
- 页面提供 **"立即发送今日汇总"** 与 **"预览"** 按钮，便于测试与补发。

## 10. 配置项（`config/config.yaml` 新增）

```yaml
# 指数 Parquet 目录（与 data_dir 并列）
index_dir: index_daily

report:
  enabled: true
  cron: "0 18 * * 1-5"
  recipients: ["your_account@outlook.com"]
  subject_prefix: "A股每日大盘汇总"
  index_codes: [sh.000001, sz.399001, sz.399006, sh.000688,
                sh.000016, sh.000300, sh.000905, sh.000852]

smtp:
  host: smtp.126.com        # 发件用 126（网易）；不用 Outlook 发信（见下）
  port: 465
  use_ssl: true
  username: "your_sender@126.com"
  from_addr: "your_sender@126.com"
  # password 从环境变量 SMTP_PASSWORD 读取（值为 126 邮箱的「客户端授权码」），不写入 config、不入 git
```

### 10.1 发件邮箱说明（重要）

- **收件人使用 Outlook 完全没问题**：邮件投递到 Outlook 收件箱即可，与发件通道无关。
- **不建议用 Outlook 做发件邮箱**：微软自 2024-09-16 起对 Outlook.com/Hotmail 个人邮箱关闭了 SMTP Basic Auth，只支持 **OAuth2 现代验证**（需注册应用 + 刷新令牌），成本高。
- 发件用 **126 邮箱（`smtp.126.com:465`，SSL）**，认证用**客户端授权码**（不是登录密码）。
- 注意：网易免费邮箱对 SMTP 有发送频率/每日发送量限制；本场景为每天 1 封、收件人极少，不受影响。
- SMTP 密码/授权码走环境变量 `SMTP_PASSWORD`，**不入 git**。

## 12. 验收标准

1. 配置好 SMTP 后，点击"立即发送今日汇总"，能收到一封包含 **①-⑥ 全部 6 个板块**的 HTML 邮件；
2. 邮件在 **Outlook** 网页端与客户端显示正常，**红涨绿跌**正确，无布局错乱；
3. 数据未就绪时，定时任务**跳过不发送**，且 `task_run`/日志可解释原因；
4. 任一板块数据缺失时，该区块显示"数据缺失"，**不造假值**；
5. 重启后端后，定时任务与配置正常恢复。

## 13. 风险与合规

- **合规**：本功能为**个人自用**的行情数据汇总，不含荐股/投资建议，风险低；若未来对外公开推送，需评估投顾资质。
- **邮件投递**：发件域建议固定（QQ/163），避免被 Outlook 判为垃圾邮件；首版若被退信，检查 SPF/发信频率。
- **指数数据可用性**：部分指数（中证1000 等）baostock 可能未收录，采用"取不到则跳过"。
