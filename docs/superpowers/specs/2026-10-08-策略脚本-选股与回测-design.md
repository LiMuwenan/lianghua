## 3. 公共约定（两脚本共用）

### 3.1 仓库根定位与配置读取

- 脚本工作目录 = 脚本所在目录，故脚本用 `Path.cwd()` 向上查找含 `config/config.yaml` 的目录作为**仓库根**（`strategy/strategy`、`strategy/backtest` 均为向上 2 级）。
- 读 `config.yaml` 的顶层键：
  - `data_dir` → 平台主数据目录（当前 `E:/资料/证券/lianghua/market`）；
  - `output_dir` → 结果输出根（默认 `outputs`，相对仓库根解析）。
- 两脚本各暴露一个 `DATA_DIR` 顶层常量，**默认 `""` 表示「自动读 config」**；用户填了才覆盖（注入机制会跳过空串）。这样既能跟随平台配置，又允许临时指向他处。

### 3.2 数据读取

- 用 **DuckDB**（`duckdb==1.5.5` 已在 [requirements.txt](file:///d:/Project/lianghua/requirements.txt)）读 `read_parquet('{data_dir}/*.parquet')`；Windows 路径需转为**正斜杠**。
- 真实列（[parquet_store.py](file:///d:/Project/lianghua/app/services/parquet_store.py#L7-L13)，共 **27 列**）：
  `date, code, open, high, low, close, preclose, volume, amount, turn, pctChg, tradestatus, isST, peTTM, pbMRQ, psTTM, pcfNcfTTM, qfq_factor, hfq_factor, qfq_open, qfq_high, qfq_low, qfq_close, hfq_open, hfq_high, hfq_low, hfq_close`
- `date` 为字符串 `YYYY-MM-DD`；`code` 为**去点带市场前缀**格式（`sh600000` / `sz000001`）。
- 价格类因子一律用 **`qfq_close`**（前复权，抹平除权跳空）；估值/量价用原始列。

> 说明：设计方案文中写「24 列」为历史笔误，实际按代码 `ALL_COLS` 的 27 列为准，脚本以实际列为准。

### 3.3 股票池过滤（每期横截面先过滤，再打分）

在**每个调仓日**的横截面上，剔除：
1. 指数：`code` 以 `sh000` / `sz399` 开头；
2. ST：`isST = 1`；
3. 非正常交易：`tradestatus != 1`；
4. 上市不足：该股截至当日累计交易日数 `< min_list_days`；
5. 流动性不足：过去 20 个交易日日均成交额 `< min_amount`。

### 3.4 因子标准化与打分（选股核心）

对**每个调仓日**的候选池做横截面处理，各因子统一为「越大越好」的分位得分（`pandas.rank(pct=True)`）：

| 因子键 | 计算 | 方向 | 得分 |
|---|---|---|---|
| `value` | `peTTM`、`pbMRQ` 各自横截面分位取均值（`peTTM<=0` 视为缺失） | 低估值为好 | `1 - pct(mean_pe_pb)` |
| `momentum` | 20 日、60 日收益率（`qfq_close / qfq_close.shift(N) - 1`）各自分位取均值 | 高动量为好 | `pct(ret)` |
| `volatility` | 20 日日收益率标准差（`qfq_close.pct_change().rolling(20).std()`） | 低波动为好 | `1 - pct(vol)` |
| `liquidity` | 20 日日均成交额（`amount.rolling(20).mean()`，取 `ln`） | 高流动性为好 | `pct(ln_amount)` |

- 缺失值（NaN）分位记 `0.5`（中性），不因单因子缺失剔除整只股票；
- 权重为 0 的因子直接跳过；
- 综合得分 `score = Σ wᵢ·sᵢ / Σ|wᵢ|`；按 `score` 降序取前 `TOP_N` 作为该期候选池；
- 权重用**扁平标量参数** `w_value / w_momentum / w_vol / w_liquidity`（因前端不支持 dict）。

## 4. 选股脚本设计（`strategy/strategy/选股-多因子打分.py`）

### 4.1 顶层常量（可被注入覆盖）

```python
START_DATE = "2020-01-01"   # 区间起
END_DATE = ""               # 空=今天
REBALANCE = "M"             # M=每月最后交易日 / W=每周最后交易日
TOP_N = 20                  # 每期选股数
W_VALUE = 1.0
W_MOMENTUM = 1.0
W_VOL = 1.0
W_LIQUIDITY = 1.0
MIN_AMOUNT = 50_000_000.0   # 20日均成交额下限（元）
MIN_LIST_DAYS = 120         # 上市最少交易日
DATA_DIR = ""               # 空=读 config.yaml
```

### 4.2 流程

1. 定位仓库根、读 config 得 `data_dir`/`output_dir`；
2. DuckDB 读全量 Parquet（列裁剪到所需列），转 pandas；
3. 按 `code` 分组算出滚动因子列（20/60 日收益、20 日波动、20 日均额），并计算「截至当日的累计交易日数」用于上市过滤；
4. 生成**调仓日序列**：`M` = 每月最后一个交易日，`W` = 每周最后一个交易日（基于区间内实际交易日）；
5. 对每个调仓日：过滤股票池（§3.3）→ 横截面打分（§3.4）→ 取 TopN；
6. 汇总所有调仓日结果，写 CSV。

### 4.3 输出

- 路径：`{output_dir}/selection/select_{START}_{END}_{REBALANCE}.csv`（`END` 为空时用实际末日；数据目录不存在则报错退出）。
- 列：`date, code, name, score, rank, value, momentum, volatility, liquidity`
  - `name` 从元库 `meta.db` 的 `stock` 表按 `code` 补（stdlib `sqlite3`；库/表缺失则该列留空，不报错）；
  - 每行 = 某调仓日的一只入选股票；同一 `date` 按 `rank`（1=最优）排序。
- 控制台打印摘要：区间、调仓日数、每期入选数、总行数、输出路径。

### 4.4 manifest（`strategy/strategy/选股-多因子打分.py.manifest.yaml`）

```yaml

  end_date:      {default: "",           type: date,  desc: "结束日期(空=今天)",      var: END_DATE}
  rebalance:     {default: "M",          type: str,   desc: "调仓周期(M/W)",          var: REBALANCE}

  w_vol:         {default: 1.0,          type: float, desc: "波动率因子权重",         var: W_VOL}

  data_dir:      {default: "",           type: str,   desc: "数据目录(空=读config)",  var: DATA_DIR}
output: outputs/selection/select_*.csv
```

## 5. 回测脚本设计（`strategy/backtest/组合调仓回测.py`）

### 5.1 顶层常量（可被注入覆盖）

```python
POOL_FILE = ""              # 选股池 CSV；空=自动取 outputs/selection 下最新一个
HOLD_N = 20                 # 每期持有数（≤ 该期池大小，超出按池大小）
COST = 0.002                # 双边交易成本（合计）
WEIGHT_MODE = "equal"       # 权重模式（本期仅 equal）
BENCHMARK = "market_equal"  # 基准：市场等权；或填一个指数 code（如 sh000300）
INIT_CAPITAL = 1_000_000.0  # 初始资金
DATA_DIR = ""               # 空=读 config.yaml
```

### 5.2 流程

1. 定位仓库根、读 config；确定池文件（给定或自动取最新）；
2. 读池文件得到各调仓日的持仓名单；DuckDB 读所需股票 `qfq_close`（复权价）日序列；
3. **净值计算**：以初始资金为起点，逐调仓期：
   - 期初按等权建仓 `HOLD_N` 只；持有至下一调仓日；
   - 期收益 = 各持仓 `qfq_close` 期收益的等权平均；
   - 换手率 `turnover` = 本期与上期持仓名单的差异比例（对称）；
   - 净值更新：`nav_t = nav_{t-1} × (1 + 期收益) × (1 - COST × turnover)`（首期按全额建仓计一次成本）；
   - 派生逐日净值序列（期内用持仓等权日收益累积到每个交易日）；
4. **基准**：`market_equal` = 过滤后全市场等权日收益累积成基准净值；指数 code 则用该 code 的 `qfq_close`；
5. 计算指标并输出。

### 5.3 输出

- 目录：`{output_dir}/backtest/bt_{tag}/`（`tag` = 池文件名 + 时间戳）。
- `nav.csv`：列 `date, nav, benchmark_nav, drawdown`
  - `nav` 起点为 1.0；`drawdown` = `nav / cummax(nav) - 1`（≤ 0）。
- `metrics.json`：

```json
{
  "run_tag": "...", "start": "2020-01-31", "end": "2026-09-30",
  "rebalance": "M", "hold_n": 20, "cost": 0.002, "benchmark": "market_equal",
  "init_capital": 1000000.0, "final_nav": 1.23,
  "total_return": 0.23, "annual_return": 0.08,
  "max_drawdown": -0.31, "sharpe": 0.65,
  "win_rate_period": 0.55, "avg_turnover": 0.40,
  "benchmark_total_return": 0.10, "excess_return": 0.13,
  "n_periods": 60
}
```

- 控制台摘要：期数、期末净值、累计/年化、最大回撤、夏普、超额。

## 9. 风险与注意事项

- **数据规模**：DuckDB 读全量 Parquet 做滚动计算，注意**列裁剪**（只读所需列）与必要时按区间过滤，避免一次性载入过多列。
- **口径简化**：回测为「收盘价调仓 + 双边成本」的简化模型，不含涨跌停/停牌/滑点，结论仅作策略初筛，不构成实盘依据（与 `readme.md` 复盘的谨慎口径一致）。
- **复权一致性**：全程用 `qfq_close`，避免除权跳空污染收益。
- **临时副本定位**：脚本不得依赖 `__file__` 定位仓库（运行的是系统 temp 副本），只能用 `Path.cwd()`。
- **manifest 字段**：用 `output`（单数字符串），与 scanner 实际读取一致。
- **git 规矩**：仅提交新增 `.py` + `.manifest.yaml` + 本 spec（+ 设计方案迭代路线补充）；不提交数据/结果文件。按逻辑单元小步提交，不擅自 push。
