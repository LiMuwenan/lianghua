# 提示词：量化交易平台 P0 一期实现

## 你的角色
你是资深全栈工程师，在 `d:\Project\lianghua` 项目下实现量化交易平台的第一期（P0）。
本提示词 + 方案文档 `docs/设计方案.md` 是唯一设计依据。请严格按文档实施，**不要扩展到 P0 范围之外**；未提之处遵循文档默认约定。

## 背景与目标
当前项目有两类独立 Python 脚本（`script/` 数据抓取参考、`strategy/strategy/` 策略回测），只能单独 `python xxx.py` 运行。**硬约束：`script/` 脚本只作参考、不参与真正运行，也不作为平台主数据**；平台主数据由其自身内建摄取直接写入 Parquet。
目标：搭建一个**本地单机 Web 平台**，把「数据管理」和「策略/回测管理」统一起来。P0 只求**跑通闭环**——平台内建「获取全量/增量数据」能力并按 Parquet 落盘，能登记/运行 strategy 下遗留回测脚本、看状态与日志、展示数据集覆盖情况；不做完整功能。

## 技术栈（硬约束，不要更换）
- 后端：Python 3.10+，**FastAPI + Uvicorn**，纯 REST API（无状态，不渲染页面/不托管前端路由）
- 元数据库：**SQLite + SQLAlchemy ORM**
- 调度：**APScheduler**（P0 可只预留接口，不做任务实例化）
- 前端：**单页原生 JS + ECharts**（无构建链），由 FastAPI 托管静态资源
- 脚本执行：**subprocess** 隔离运行，实时抓取 stdout/stderr 写入日志文件
- 明确不引入：Celery / Redis / 登录鉴权 / 多进程调度；CORS 仅放行本机来源（127.0.0.1、localhost）

## P0 必须完成的模块
1. **manifest 扫描器**：扫描 `strategy/strategy/` 下的 `*.py.manifest.yaml`，登记可运行的回测脚本（name/kind/script 路径/params schema/data_dep/output）到元数据库；`script/` 仅作为只读参考目录列出、**不生成可运行任务**。
2. **数据管理（平台内建摄取）**：提供**单一「获取数据」**（全量/增量/复权合一，支持可选**起始日期**，按元数据库每股最新日期断点跳过已有日期，逐股 merge 重写 Parquet）；数据源用 **baostock**。运行后展示「最新数据日期、滞后天数」。
3. **策略/回测管理**：触发策略脚本运行（支持参数覆盖），记录运行状态与历史，可查看日志。
4. **任务管理**：`task_run` 记录状态（排队/运行中/成功/失败/部分失败）、开始结束时间、退出码、日志路径、结果摘要。
5. **前端页面**：数据管理页、策略/回测页、任务列表页（含日志查看）。

## 关键实现约定
- **不改原脚本逻辑与文件**；参数通过 subprocess 注入（优先命令行/环境变量，不支持时用临时参数化副本，保留原文件）。
- 平台主数据为 `data/market/` 下按股票的 Parquet；`script/` 旧 CSV 仅作遗留参照。**SQLite 只存元数据**（脚本登记、任务运行记录、数据集状态、每股 latest_date 断点续传）。
- 元数据库表结构参考方案文档 6.3（dataset/strategy/task_run；cron_task 可先建表不启用）。
- `params` 采用方案文档 7.1 的 manifest 声明式（default/type/desc）。params schema 入库后，前端据此动态渲染表单。
- 代码注释使用中文；日志统一 UTF-8。
- 提供后端启动命令（如 `uvicorn app.main:app --host 127.0.0.1 --port 8000`）。

## 验收标准
- 启动后浏览器可打开平台，能看到「数据 / 策略 / 任务」三个页面。
- 能在 UI 触发一个**真实脚本**，任务经历「排队→运行中→完成」，能查看其状态、退出码与日志。
- 元数据库能持久记录脚本与运行历史，**后端重启后仍在**。
- 数据集页能展示最新数据日期/滞后天数（基于 Parquet 实际扫描得出，不应造假值）。
- 至少能在 UI 触发一次「获取增量数据」，确认生成/更新了对应股票的 `.parquet`，且最新日期、滞后天数随结果更新。
